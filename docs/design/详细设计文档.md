# 详细设计文档

> ToolBox 的架构设计、模块职责与关键流程。配套阅读：`AGENTS.md`（编码规范）、`技术栈文档.md`。

## 1. 架构总览

纯前端 SPA（Vite build 产物 + 静态托管 SPA fallback），数据 100% 本地处理。

```
main.tsx（引导：语言协商 → i18n 初始化 → 挂载）
 └─ AppProviders（next-themes ThemeProvider → RouterProvider → sonner Toaster）
     └─ router（plugins/router.tsx，路由由工具注册表生成）
         └─ BaseLayout（layouts/，薄装配：Tooltip 上下文 + AppShell + CommandPalette）
             └─ AppShell（layouts/app-shell/，悬浮 dock + 顶部胶囊 + 唯一滚动区 main）
             ├─ HomePage（收藏/最近使用/全部分类）
             ├─ ToolPage ×71（ToolLayout 页头 + lazy 工具组件）
             ├─ AboutPage / NotFoundPage
             └─ CommandPalette（Ctrl/Cmd+K 全局搜索）
```

分层原则：

- `tools/<分类>/<工具>/service.ts`：**纯逻辑层**，零 DOM/React 依赖，可直接单测；
- `tools/<分类>/<工具>/*.tsx`：**视图层**，只做输入采集、调用 service、渲染结果；
- `stores/`：仅存全局跨页状态；工具内部状态一律组件局部。

## 2. 工具注册表（核心机制）

### 2.1 类型

```ts
// src/tools/define-tool.ts
interface RawTool {
  name: string // = 目录名 = path 去斜杠 = i18n 键
  path: string // '/hash-text'
  keywords: string[] // 中英混合搜索词
  icon: LucideIcon
  component: () => Promise<{ default: ComponentType }> // 加载器
  createdAt?: string // 两周内自动 isNew
  redirectFrom?: string[] // 旧路径重定向
}
interface DefinedTool extends RawTool {
  lazyComponent: LazyExoticComponent
} // defineTool 时模块级创建
interface Tool extends DefinedTool {
  isNew: boolean
  category: CategoryKey
} // 注册中心挂载
```

`defineTool()` 在**模块作用域**调用 `lazy()` 一次（禁止渲染期创建组件，
react-hooks/static-components 约束）。

### 2.2 注册链路

```
src/tools/<分类>/<工具>/index.ts   export const tool = defineTool({...})
        ↓
src/tools/<分类>/index.ts          export const <分类>Tools: DefinedTool[] = [toolA, toolB…]
        ↓
src/tools/index.ts                 toolsByCategory: ToolCategory[]（分类顺序即展示顺序）
                                   ├─ tools（全量扁平）
                                   ├─ getToolByPath / getFavoriteTools / getRecentTools
```

新增工具的注册只涉及分类目录一个文件的改动；分类目录互不依赖，可并行开发。

### 2.3 路由生成

`plugins/router.tsx`：工具路由 = `tools.map(tool => ({ path, element: <ToolPage/> }))`；
`redirectFrom` 生成 `loader: () => redirect(newPath)`；`*` → 404；根路由 errorElement → RouteError。

## 3. 布局设计（响应式）

断点（`composable/use-breakpoint.ts`）：手机 `<768`、平板 `768–1279`、PC `>=1280`。
布局形态由 `layouts/app-shell/dock-logic.ts` 的 `resolveShellLayout` 一处决定。

| 区块   | PC / 平板                                           | 手机                                                  |
| ------ | --------------------------------------------------- | ----------------------------------------------------- |
| 导航   | 左侧悬浮图标条 dock（首页 + 9 分类，不占内容宽度）  | 底部三段 dock：主页 / 齿轮 / 菜单                     |
| 二级项 | 悬停分类 → 右侧滑出浮层面板（盖住内容，不挤压布局） | 「菜单」让 dock 原地变形为卡片：分类网格 → 该分类工具 |
| 顶部   | 左上面包屑 + 右上胶囊组（平板把外链收进「更多」）   | 无顶栏，功能全部并入底部 dock                         |
| 内容区 | `<main>` 为唯一滚动容器，按 `--shell-inset-*` 让位  | 同左，底部给 dock 让位                                |

- 手机齿轮：点击让五个快捷入口（亮度 / 翻译 / 搜索 / 关于 / GitHub）沿上半圆散开到 dock 上方，
  齿轮自身放大并旋转；收起时原路收回并反向错开，即「收纳盒」效果。落点由纯函数
  `fanSlots(count, radius)` 算出（150°→30° 对称分布）。语言/主题的下拉要展开时会先把扇形收起，
  避免两层浮层叠在一起。

- **app-shell 滚动模型**：根容器 `h-svh overflow-hidden`，`<main data-app-shell-scroll>`
  是唯一滚动容器；dock 与胶囊是根的直接子节点，用 `absolute` 浮在滚动区之上，
  **不放 sticky**（移动端浏览器工具栏伸缩会改变视口高度，sticky 头部会随之位移）。
  留白全部走 `index.css` 的 `--shell-inset-*` / `--shell-immersive-inset-*` 令牌：
  沉浸工具只让出顶部胶囊的高度、不留左右与底部留白，否则会比改造前少几十像素而顶出内部滚动条。
- 顶栏不再有背景条与分隔线：整行 `max-w-5xl` 居中 + 上下左右内边距，宽屏时两组胶囊明显向内收，
  视窗变窄再逐层退到 24px 内边距。左组 = logo 胶囊（图标 + 站名）；换页时其右侧**分离出**
  一颗面包屑胶囊（分类 › 工具名），用 motion 的 `width: 0 → auto` + spring 完成，
  与首页 gooey 搜索框同一套动效语言。
- 右组操作胶囊（`components/action-pill.tsx`）：平时只露 44px 圆形图标，悬停 / 聚焦 / 菜单展开时
  用 `grid-template-columns: 0fr → 1fr` 在图标右侧长出文字，并把相邻胶囊真实挤开——
  因此顶栏**不再使用 Tooltip**（dock 图标条仍然用）。搜索那颗例外：⌘K 键帽走 `persistent` 槽常驻，
  收起态就是胶囊而不是圆。
  注意轨道收起时必须真的到 0：间距要写在被 `overflow-hidden` 裁切的**内层**，
  写成药丸的 `gap` 或被裁切层的 `padding`（border-box 下 padding 是宽度下限）都会让圆差 8px。
- dock 键位无边框、无共享背板：悬停与选中都用中性灰阶（`bg-foreground/10` 与 `/15`），
  绿色只留给图标本身。选中背板是每颗键的静态背景，**不用 motion 的 `layoutId` 共享元素**——
  共享元素在 `activeKey` 跳变时会先把旧背板投影回原位再飞过来，表现为点击分类时抖一下。
- 二级浮层是**悬停即出、点击固定**：`useDockController` 分 `hovered` 与 `pinned` 两个态，
  `visibleCategory = hovered ?? pinned`——移开鼠标会回落到被固定的那个分类，而不是直接关掉。
  图标条与浮层共用一个 `pointer-events-auto` 悬停容器，否则鼠标横穿两者之间那道缝隙时
  浮层会先关掉、点不到里面的工具。分类键**不再出 Tooltip**（浮层头部已经写了分类名），
  只有首页键保留。
- 浮层头部只显示一级分类（图标 + 名称 + 工具数），无分割线。左侧那颗菱形箭头必须对准
  对应的分类键，而浮层默认与图标条垂直居中、分类键不在中线上，所以浮层整体按
  `键中心 − 28px` 平移、箭头偏移再按视口夹取。测量用 `offsetHeight` 而不是
  `getBoundingClientRect`：后者会把 motion 正在施加的 translateY 也算进去，拿它反推位移就成了循环。
- 主题键与语言键都是**点按循环**而不是下拉，两档以上的偏好用列表选属于多点一次：主题走
  浅色 → 深色 → 跟随系统 → 浅色（纯函数 `nextTheme`），语言走中英互换（`nextLocale`，
  加第三档就自动变循环）。跟随系统必须留在环里，它就是首访默认档，只留两态的话用户点一次
  就永远回不到跟随。图标读的是**当前**档：主题用 Sun/Moon/Monitor，语言用文字徽标
  「中」/「A」（字体渲染，占 `size-5` 图标位，`aria-hidden`；`ActionPill` 的 `icon` 因此收的是
  `ComponentType<{ className?: string }>` 而不是 SVG 组件），顶栏悬停长出的文字与
  `aria-label` / Tooltip 说「现在是什么、点一下会变成什么」。三种外观共用同一颗按钮：顶栏
  `variant="pill"`、手机 dock `variant="dock"`（`iconOnly`，触屏没有 hover）、简历编辑器
  独立壳 `variant="icon"`。语言名按 endonym 惯例留在组件常量里（英文界面也显示「简体中文」），不进口语包。
- dock 键位：同一时刻只开一个浮层，Esc / 换页 / 点浮层外均收起。键盘按 W3C toolbar 模式做
  roving tabindex，整条 dock 只占一个 Tab 站点，方向键在键位间移动。
- 浮层面板与手机卡片都只列**一个分类**的工具（`layouts/nav-list.tsx`，分类选择由调用方负责）；
  卡片头部保留返回与收起两个键，因为触屏没有"移开鼠标就收"这回事。
- 手机卡片不再是底部上滑的 Sheet，而是横向 dock 的原地形变：外壳常驻 motion 的 `layout` 投影，
  条与卡片在同一个 `AnimatePresence mode="popLayout"` 里互为进出场，尺寸完全由内容决定、不测像素，
  两端的圆角由 motion 在投影期间插值。`overflow-hidden` **只在卡片态挂**：常驻会把齿轮散开的
  扇形键削掉（那五个键本来就浮在条上方 132px 的溢出区里）。进场的二级内容延迟 0.14s 淡入，
  把形变最扭曲的那一截交给外壳的缩放独自扛。
- 备案号属法定信息，按站点惯例**只在首页页脚**出现（跟着 `<main>` 内容滚动的普通页脚，
  不是悬浮层）；工具页与手机导航卡片都不显示，免得白占正文高度。
- 沉浸式工具页（`immersive: true`）上，第一次点内容区就把 dock 折成左下角一颗按钮
  （`isDockCollapsed`：只在沉浸页成立，并比对折叠时所在的路由，换页即自动展开）；
  点那颗按钮展开，收起与展开都是向左下角收拢的 spring 动效。那颗按钮抬在 `bottom-20`，
  因为画布类工具自己的工具条就贴在左下角（AI 生图缩放条占 bottom-3 起约 56px），
  放 `bottom-3` 会和它叠成一条。悬停色调走 `dockItemClass(active, 'accent')`。
  顶部胶囊**不跟着收**，搜索/语言/主题在画布上仍要随时可达。普通工具页的 dock 常驻不折——
  那里要靠它频繁切工具。已废弃早先"鼠标静止 300ms 变暗"的做法。
- 工具页 `ToolLayout`：图标 + H1 + NEW 徽标 + 收藏星标 + 描述 + 内容容器；
  SEO meta 由 React 19 原生 `<title>/<meta>` 提升（`modules/seo/document-meta.tsx`）。

## 4. 状态管理

| store（`src/stores/`） | 字段                                                               | 持久化                   |
| ---------------------- | ------------------------------------------------------------------ | ------------------------ |
| `preferences.store`    | locale（zh/en）、activeCategory                                    | `toolbox.preferences` v5 |
| `tools.store`          | favorites: string[]（路径有序）、recent: {path,count,lastUsedAt}[] | `toolbox.tools` v1       |
| `search.store`         | open（Palette 开关）                                               | 不持久化                 |

- `activeCategory` 只记住上次打开的分类，用于图标条高亮；**加载时不自动弹面板**。
  v5 起废弃 `expandedCategories` 与 `sidebarCollapsed`（dock 不占内容宽度，折叠态失去意义）。

- 主题持久化由 next-themes 负责（key `theme`），不入 zustand。
- 所有 persist store 自定义 `merge`：逐字段类型校验 + 兜底（localStorage 可能被改坏）。
- 最近使用：进入工具页时 `recordVisit(path)`（次数 +1、刷新时间戳，上限 50 条）；
  "常用工具" = 按 count 降序、lastUsedAt 次序取 Top 8（`getRecentTools`）。

## 5. 搜索设计（Command Palette）

- 入口：顶栏按钮 / 首页按钮 / `Ctrl+K`（Mac `Cmd+K`），`stores/search.store` 控制开关。
- 数据：`useToolSearchItems()` 汇总 71 工具 → {tool, 当前语言标题, 另一语言标题, 描述, keywords}；
  fuse.js 权重：title 2 / altTitle 1.5 / keywords 1 / name 1 / description 0.5，threshold 0.35。
- cmdk 仅做键盘导航与展示（`shouldFilter={false}`），过滤完全交给 fuse；
  空查询展示：快捷操作 + 收藏夹 + 最近使用 + 全部分类；结果按分类分组渲染。
- 动作项：随机工具 / 切换深色模式 / GitHub / 关于。

## 6. i18n 设计

- 语言包：`src/modules/i18n/locales/{zh,en}/*.json`，**文件名即命名空间**：
  `common`、`categories`、`home`、`about`、`not-found`、`tools-<分类key>`。
- 工具文案键：`<工具名>.title` / `<工具名>.description`（工具私有键可继续挂在同一命名空间下）。
- 加载策略：首屏仅加载协商出的语言（`resolveInitialLocale`：持久化 → 浏览器语言 → zh），
  另一语言后台预载（跨语言搜索零等待）；切换语言 `changeLocale` 先加载再生效。
- 组件取词：`useTranslation('<ns>')`；跨命名空间取词用 `t('tools-crypto:hash-text.title')`。

## 7. 主题设计

- next-themes `attribute="class"`：html 元素挂 `.dark`，Tailwind `@custom-variant dark` 生效。
- 令牌：`src/index.css` 以 oklch CSS 变量定义 `--primary/--background/…`，
  亮暗两套；主色品牌绿（亮 `oklch(0.63 0.15 156)` / 暗 `oklch(0.72 0.15 156)`）。
- highlight.js 不引第三方主题，`index.css` 自带极简双主题 token（`.hljs-*` + `.dark .hljs-*`）。

## 9. SEO / 站点地图

- 运行时：每个页面渲染 `<title>` + `description` + `og:*`（React 19 hoisting）。
- 构建期：`scripts/generate-sitemap.mjs`（**prebuild** 在 `vite build` 之前执行）扫描
  `src/tools/*/*/index.ts` 的 `path:` 字段生成 `public/sitemap.xml` 与 `public/robots.txt`；
  域名取 `src/config/site.ts` 的 `siteUrl`（单一来源），环境变量 `SITE_URL` 仅作临时覆盖。
  这两个文件已 gitignore，且 Vite 在 build 开始时就拷贝 `public/` → `dist/`，
  因此不能挂 postbuild：那样产物里永远缺这两个文件，线上会回退成 SPA 的 index.html。

## 10. 错误处理约定

- service 抛 `Error`（英文技术信息）；UI 层 try/catch 转 Alert/文案，禁止页面崩溃。
- 路由级兜底：`RouteError`（errorElement）；404 由 `*` 路由承接。
- 复制降级：`navigator.clipboard` 不可用时回退 `execCommand`，再失败 toast 提示。

## 11. 图片压缩转换工作台（image-compressor，移植自 tools-pic 图小小）

- **位置**：`src/tools/images/image-compressor/`，作为图片分类的普通工具页（/image-compressor）。
- **引擎层** `engines/`：与 UI 完全解耦，1:1 移植自 tools-pic——
  `image-base`（尺寸计算/裁剪/预览抽象）、`jpeg-image`（mozjpeg）、`png-image`（imagequant 量化 + oxipng 优化）、
  `avif-image`、`gif-image`（gifsicle wasm，支持动画与 resize）、`svg-image`（svgo）、`canvas-image`（浏览器编码兜底）、
  `queue`（并发队列）、`animation`（动图字节检测）、`handler`（convert 分发）、`compress.worker` / `preview.worker`
  （Vite `new Worker(new URL(...), { type: 'module' })`）。
- **WASM 产物**：`scripts/prepare-codecs.mjs`（predev/prebuild 钩子）把 `@squoosh-kit/*` 的浏览器产物拷到
  `public/codecs/<name>/`（gitignore）；gifsicle 产物直接提交在 `public/codecs/gif/` 与 `public/wasm/gif.wasm`。
  运行时 Worker 内 `import(/* @vite-ignore */ '/codecs/<name>/index.browser.js')` 动态加载并缓存。
  **入口统一用 `.js` 而非 `.mjs`**：部分静态托管（如腾讯云 EdgeOne Pages）的 MIME 表没有 `.mjs`，
  会返回 `application/octet-stream`，浏览器按严格 MIME 校验直接拒绝当作模块加载。
  **dev 注意**：Vite 会给动态 import 注入 `?import` 并拒绝以模块方式加载 public 目录文件——
  `vite.config.ts` 的 `serve-public-codecs` 中间件 unshift 到中间件栈顶先行响应（仅 serve 模式生效）。
- **主线程装配** `use-compressor-worker.ts`：双 Worker 生命周期、消息回写（字段级更新）、
  批量派发限速（每 8 条一批让出主线程）。
- **状态** `store.ts`：zustand——`list`（Map<number, ImageItem>，含原图/压缩结果/状态）、生效选项 `option` 与
  编辑态 `tempOption`；persist 只存 option，读取经 `normalizeCompressOption` 校验兜底（沿用 tools-pic 的归一化）。
- **UI**：空态=上传区（点击/拖拽含文件夹递归/剪贴板粘贴）；有文件=统计摘要 + 文件列表（预览缩略图点开全屏
  前后对比滑块，棋盘格透明底）+ 右侧选项面板（resize 七模式、输出格式转换、各格式参数按可见性联动、
  重置/应用）；PC 端 ResizablePanel 左右分栏，移动端上下堆叠。
- **约束**：Worker 内不能访问主线程 URL.createObjectURL 之外的 DOM——引擎层只用 OffscreenCanvas/Canvas API；
  HEIC 解码（heic-to/next）仅在遇到 HEIC 文件时动态加载；输出格式浏览器不支持编码时保留原图并提示。

## 12. 性能策略

- 路由/组件级代码分割：每工具一个 chunk（rolldown 自动提取共享模块）。
- 语言包按命名空间惰性加载；highlight.js 仅引 `lib/common` 子集。
- 大输出渲染（Base64 文件、hash 全量）限制展示行数，完整结果一键复制。
