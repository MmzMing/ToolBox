# 图片堆叠（拼接 / 拆分）设计

日期：2026-09-25 · 状态：P1 已实现 · 分类：images · 路由：`/image-stack`

## 0. 一句话目标

一个纯本地的图片排版工具：把多张图按**预设模板**拼成一张成品（长图 / 九宫格 / 海报），
或把一张图按**网格模板**切成多张（朋友圈九宫格 / 印刷切片），两者共用同一套画布比例、
样式与导出面板。

## 1. 竞品调研

| 产品              | 拼接                       | 拆分            | 样式控制                   | 导出       |
| ----------------- | -------------------------- | --------------- | -------------------------- | ---------- |
| 腾讯帮小忙九宫格  | 无                         | 仅 3×3          | 无                         | 打包下载   |
| 2345 看图王       | 横/竖/长图 + 模板/自由拼图 | 无              | 边框、背景、间距（无圆角） | JPG/PNG    |
| Canva 合并图片    | 长图为主                   | 无              | 弱                         | 云端处理   |
| Instagram Grid 类 | 无                         | 3×3 / 3×6 / 3×9 | 仅比例裁切                 | 逐张       |
| 通用 Collage App  | 模板数量为核心卖点         | 无              | 边框/间距/圆角/背景/比例   | 分辨率受限 |

可打的空白：① 拆分侧普遍只有 3×3，缺自定义行列与不等分切割线；② 拼接侧要么纯预设要么纯
自由画布，少有「预设模板 + 模板内微调」；③ 竞品全是云端上传，纯本地是硬优势；④ px 级数值
化控制 + 精确像素尺寸导出，拼图站基本没有。

## 2. 决策记录

| 决策点     | 结论                                             | 理由                                                                                                                    |
| ---------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 产品形态   | 单工具双模式 Tab（拼接 / 拆分）                  | 用户拍板。两个模式共享画布比例、样式、导出三块面板，代码复用最大                                                        |
| 拼接能力   | 预设模板 + 单元格内微调（P1），自由堆叠画布排 P3 | 用户拍板要双轨，但自由画布单独占近一半工作量，分期交付                                                                  |
| 拆分表达力 | 等分网格 + 可拖拽切割线（不等分，P2）            | 用户拍板。覆盖「大图 + 侧栏」这类不均衡版式                                                                             |
| 画布尺寸   | 比例 + 预设尺寸档 + 自定义                       | 用户拍板。1:1→1080×1080、3:4→1080×1440、9:16→1080×1920、16:9→1920×1080，也能自己填                                      |
| 样式丰富度 | 纯色/透明背景 + 边距/间距/单元格圆角/画布圆角    | 用户拍板，YAGNI 砍掉渐变、阴影、图片背景、模糊延伸                                                                      |
| 导出能力   | 格式与质量 + 拆分打包 zip + 剪贴板与全屏预览     | 用户拍板。「方案预设保存复用」被砍                                                                                      |
| 渲染引擎   | 原生 Canvas 2D 单一真相源 `renderSceneToContext` | 预览与导出走同一个函数 ⇒ 像素必然一致。淘汰 html2canvas-pro（精度不可控、做不到精确像素）与双渲染器（两套逻辑必然漂移） |
| 手柄层     | DOM overlay 叠在 canvas 上                       | 拿到原生事件与 CSS cursor，不必手写命中测试的光标管理（Figma/tldraw 常见做法）                                          |
| 新增依赖   | 无                                               | 原生 Canvas 2D + 已有的 jszip 够用，取色用原生 `<input type="color">`，符合 AGENTS.md §12                               |

## 3. 核心洞察：拼接与拆分共用 `GridTemplate`

拼接是「N 张图 → 一个网格」，拆分是「一张图 → 一个网格的 N 个格子」。数据层是同一个东西：

```ts
type GridTemplate = {
  id: string
  cols: readonly number[] // 归一化权重，和为 1。[0.5,0.5] 两等分；[0.25,0.5,0.25] 即 1:2:1
  rows: readonly number[]
  cells: readonly GridCell[]
}

type GridCell = { col: number; row: number; colSpan?: number; rowSpan?: number }
```

一个类型同时承载三类需求：预设拼接模板（网格 + 不规则跨格）、预设拆分模板（3×3 / 3×9 / 1×3）、
自定义拆分。**拖拽切割线的本质就是改 `cols`/`rows` 里的归一化权重**，不需要为切割线另设数据结构
—— 这让 P2 几乎是免费的。

### 3.1 坐标系：布局归一化，样式绝对像素

- **布局用 0..1 权重**：切换画布比例/尺寸时布局自动适配，图片不跳位。与
  `image-to-beads/selection.ts:1` 的比例选区模型一致。
- **样式用画布真实 px**：`padding: 24` 就是导出图上的 24px，切尺寸时数值不变（视觉占比会变）。
  这是 Canva/PS 的行为，可预测。

## 4. 数据模型

```ts
type Scene = {
  canvas: { width: number; height: number } // 由 ratio + 尺寸档/自定义推出的精确像素
  style: SceneStyle
  grid: { template: GridTemplate; layers: readonly GridLayer[] }
}

type SceneStyle = {
  padding: number // 画布四周留白 px
  gap: number // 单元格间距 px
  cellRadius: number // 单元格圆角 px
  canvasRadius: number // 画布圆角 px（>0 时四角透明，仅 PNG/WebP 有意义）
  background: { type: 'color'; value: string } | { type: 'transparent' }
}

type GridLayer = {
  imageId: string | null // null = 空格子，导出时露背景
  fit: 'cover' | 'contain'
  focus: { x: number; y: number; zoom: number } // cover 裁切偏移，x/y ∈ [-1,1]，zoom ∈ [1,4]
}
```

单向数据流：**用户操作 → 改 store 里的 scene → rAF 重绘 canvas**。渲染唯一入口
`renderSceneToContext(ctx, scene, resolveAsset)`（仿 `image-to-beads/grid-render.ts:20`），
预览画到屏幕 canvas，导出画到同尺寸 OffscreenCanvas。

`resolveCells(template, box, spacing, snap)` 是纯函数，把归一化模板 + px 样式求解成矩形数组，
是单测的主战场。`snap=true` 时轨道边界取整，保证拆分切片**无缝且不重叠**（最后一块吸收取整误差）。

### 4.1 cover 填充的焦点模型

```
scale = max(cell.w/img.w, cell.h/img.h) × zoom      // zoom ≥ 1，保证始终铺满
sw = cell.w / scale ; sh = cell.h / scale            // 实际可见的源图像素
sx = (focus.x + 1) / 2 × (img.w - sw)                // focus ∈ [-1,1]，0 = 居中
```

拖拽单元格时 `focus.x -= dx / cellDisplayWidth × 2`，即拖过半个单元格走完整个裁切行程。

```
    ├── TemplateGallery.tsx   # 模板缩略图选择器

```

两个刻意决定：

1. **图片资产不进 zustand persist** —— ImageBitmap 不可序列化且 localStorage 存不下。只持久化
   样式、画布比例、导出参数，仿 `image-compressor/store.ts:55`。
2. **双级位图** —— 预览用降采样 bitmap（最长边 1600）保证拖拽流畅，导出用原始 bitmap 保证画质。

## 6. 组件与交互

页面骨架：顶部模式 Tabs（拼接 / 拆分）→ 左侧舞台 + 素材条，右侧参数卡片，沿用
`ImageToBeads.tsx:302` 的 `grid lg:grid-cols-[minmax(0,1fr)_20rem]`。不新建滚动容器
（AGENTS.md §6 app-shell 约定）。

**素材分配**（拼接模式）：新增图片或换模板后，空格子按顺序自动补上未使用的素材
（`images[i] → cells[i]`，已落位的格子不动）。手动调整四条路径：

- **单元格内拖拽** = 平移该格图片的显示区域（focus），双击复位；
- **拖出单元格** = 同一次手势改判为搬移，落到别的格子即交换两格的图（目标为空就是移动），
  跨出瞬间回滚刚才那段平移，避免搬图时顺带把裁切框挪了；同时源格盖一层中性纱表示空出来，
  并渲染一个跟手倾斜的浮层卡片（`position: fixed` + 原图缩到格子的 0.7 倍）作为拖拽影像，
  落点格用蓝色虚线框 + 淡底高亮；松手在格子外即取消，不落位也不留残影；
- **素材条拖到单元格** = 把该素材落进目标格，可重复拖同一张（原生 HTML5 DnD，
  自定义 MIME `text/x-image-stack`）；
- **点选** = 点缩略图拿起「画笔」，再点单元格落位（触屏与键盘路径）。

素材条不用 `@dnd-kit`：它的 PointerSensor 会和「拖去画布」抢同一次指针序列，
而重排本身用原生 drop 到相邻缩略图就够了。

**拆分模式**：素材条点击即选定切分源图；预览用 `<img>` 叠一层 CSS Grid 切割线（不走 canvas，
省一套渲染），编号与导出文件名同为行主序；比例感知裁切提供 居中 / 顶部 / 底部 三个锚点，
且只在原图比目标比例更高时才可用（横图裁切固定居中，锚点无意义时禁用而不是隐藏）。

**导出**：拼接 → 单张 blob → 下载 / 剪贴板 / 全屏预览（复用 `components/image-lightbox.tsx`）。
拆分 → 每格一张 blob → jszip 打包，命名 `{原名}_{行}-{列}.{ext}`，同时给逐张下载。

## 7. 错误处理

| 场景                              | 处理                                                                                            |
| --------------------------------- | ----------------------------------------------------------------------------------------------- |
| 解码失败（损坏文件 / 不支持格式） | 该素材标记 `error` 并在缩略图上显示原因，不阻塞其他图                                           |
| 图层数 < 单元格数                 | 空格子导出时露背景色，预览时画占位提示，不报错                                                  |
| 图层数 > 单元格数                 | 多余素材留在素材条未使用，不报错                                                                |
| 画布尺寸非法（0 / 负 / 非有限）   | service 内 `throw Error`（英文技术信息），UI 层捕获降级                                         |
| 画布超大                          | `MAX_CANVAS_SIDE = 8192`、`MAX_CANVAS_AREA = 33_554_432` 提前拦截，避免 canvas 静默失败或内存爆 |
| 样式数值越界                      | `clampStyle` 归一化（负数归零、上限截断），persist 读取时也过一遍                               |
| 剪贴板 API 不可用                 | 按钮禁用 + Tooltip 说明（Firefox/Safari 部分场景）                                              |
| 位图与 objectURL 泄漏             | `assets.ts` 统一 `close()` / `revokeObjectURL()`，卸载与移除素材时回收                          |

| 版式目录用「经典族 + 递归切分」两级       | 经典族（均分带、近方网格、主图四向、2×2 主图错落、1:2:1）先入列保证常用形状一定在且靠前；再用递归 `shapes(n, budget)` 生成不等宽错落排布：叶子是因式分解出的均分网格，内部节点是一次不对称切分，两侧各自继续递归。只切一层的话每段内部只能均分，出来的就永远是等比拼接。全部先算成归一化矩形，再由 `rectsToTemplate` 收集网格线反推成 `GridTemplate`，所以任何切法都能表达 |
| 右侧栏重排：画布工具条 + 导出弹窗         | 四张卡叠到约 1400px 高，调个间距要滚两屏。改成：比例 chips、尺寸档（拼接）/ 保留位置（拆分）、导出按钮收进画布正上方的工具条，导出动作与格式/质量进 Dialog；侧栏只留模板与样式两张卡，整页一屏放得下。行列 slider 只在自定义档出现（预设档它没有任何作用），单元格下方的操作提示挪到底部说明区，因为它是「读一次就够」的文案而不是要看数值调的东西                         |
| 版式打分与反差分档                        | 按最大/最小格面积比把铺法分成 0~3 四档（均匀 / 轻度 / 强 / 极端），取样时四档轮转而不是纯按分数排——纯分数会让均分网格霸榜，目录又退回等比拼接。打分本身 = 网格线数 + 短边过窄罚，**刻意不罚「格子大小不一」**，那正是错落排布要的效果；再按量化后的矩形集合做签名去重，避免同一形状从不同切法重复出现                                                                      |
| 组合数靠三层预算收敛                      | `SPLIT_RATIOS` 四档切分比 + `MAX_BUDGET = 2` 层嵌套 + 每层 `diversify` 收敛到 `SHAPE_CAP = 28`；组合子节点时两侧各只取 `BRANCH_LIMIT = 7` 个头部铺法。没有最后这层，16 张那档要枚举上万种铺法，首次生成 6.3 秒直接卡住页面（也跑不过 5 秒超时的测试）；补上之后同一档 0.5 秒                                                                                               |
| 经典族补上 bento 错落排布                 | 递归切分的采样会漏掉「左上主图 + 右列 + 底行」这种海报形状（它要求两条轴同时不对称，而每层只取头部 7 个铺法），所以把它提成经典族钉死：`bento(cols, rows)` 让主图吃下 (cols-1)×(rows-1) 的块，剩余沿右列与底行排布，总格数 = cols + rows。同一张数下取 5 个横纵比例再加 2 个镜像，等分轨道下主图与最小格的面积差就有 6~56 倍                                               |
| 拆分裁切框改为可拖拽缩放                  | `splitAnchor` 三档换成 `splitFocus`（同一套 `[-1,1] + zoom` 语义，与拼接单元格焦点一致）。`cropRectForFocus` 先取源图内放得下的最大目标比例框，再按 zoom 收缩、按 focus 平移，这个映射与 `zoomFocus` 内部的 cover 计算完全同构，所以拖拽与滚轮直接复用 `panFocus` / `zoomFocus`，不必为拆分再写一套手势数学。双击复位                                                      |
| 版式张数与素材数解耦                      | 目录原本按 `readyIds(items).length` 生成，结果只放 1 张图时模板区就塌成 1 个版式，整套错落排布根本翻不到——而一张素材重复铺进多格本来就是支持的用法。改由 store 的 `stitchCells`（1~16，持久化）驱动，模板区右上角给一个张数选择器；上传时只把它**往上抬**到素材数，删图不回落。`autoAssign` 相应改成按素材数取模循环，一格一图到九格同图都能一键铺满                       |
| 生成 id 是 `gen-<序号>` 位置式            | 目录按张数成套，形状之间没有稳定的族名可言。所以张数变化时选中态回退到第一个版式——这与参考站「先选张数再挑布局」的心智一致                                                                                                                                                                                                                                                 |
| 主图族用不等权重                          | 主图固定占该轴 62%，其余格子平分剩下的部分。等分 + 跨格表达不出「主图真的更大」                                                                                                                                                                                                                                                                                            |
| 格内滚轮缩放                              | `zoomFocus` 先算出光标对应的源图像素坐标，再按新的可见区宽度反解裁切起点，所以缩放锚在光标上而不是把画面甩走。React 的 `onWheel` 是 passive 监听拦不住页面滚动，故挂原生 `passive: false` 监听                                                                                                                                                                             |
