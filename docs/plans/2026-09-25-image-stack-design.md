# 图片堆叠（拼接 / 长图 / 拆分）设计

日期：2026-09-25 · 状态：P1 与长图档已实现 · 分类：images · 路由：`/image-stack`

## 0. 一句话目标

一个纯本地的图片排版工具：把多张图按**预设模板**拼成一张成品（九宫格 / 海报），
按**纵向流**堆成一张超长图（无缝长图 / 台词字幕 / 滚动截图去重叠），
或把一张图按**网格模板**切成多张（朋友圈九宫格 / 印刷切片）。

前两档共用画布比例、样式与导出面板；长图档是纵向流，没有格子也没有比例，
所以自带一条几何管线（`long-stack.service.ts`）。三档都是成品在左、工具栏在右。

## 1. 竞品调研

| 产品              | 拼接                       | 拆分            | 样式控制                   | 导出       |
| ----------------- | -------------------------- | --------------- | -------------------------- | ---------- |
| 腾讯帮小忙九宫格  | 无                         | 仅 3×3          | 无                         | 打包下载   |
| 2345 看图王       | 横/竖/长图 + 模板/自由拼图 | 无              | 边框、背景、间距（无圆角） | JPG/PNG    |
| Canva 合并图片    | 长图为主                   | 无              | 弱                         | 云端处理   |
| Instagram Grid 类 | 无                         | 3×3 / 3×6 / 3×9 | 仅比例裁切                 | 逐张       |
| 通用 Collage App  | 模板数量为核心卖点         | 无              | 边框/间距/圆角/背景/比例   | 分辨率受限 |

可打的空白：① 拆分侧普遍只有 3×3，缺自定义行列与不等分切割线；② 拼接侧要么纯预设要么纯
自由画布，少有「预设模板 + 模板内微调」；③ 竞品全是云端上传，纯本地是硬优势；④ px 级数值
化控制 + 精确像素尺寸导出，拼图站基本没有。

### 1.1 超长图这一档的竞品（2026-09 复查）

| 产品                        | 纵向拼接 | 台词/字幕堆叠 | 重叠自动去重 | 分段/切割   | 其他                     |
| --------------------------- | -------- | ------------- | ------------ | ----------- | ------------------------ |
| Picsew                      | 无缝     | 无            | 主打卖点     | 导出 PDF    | 打码涂抹、标注、设备边框 |
| 长图拼接大师 / 各类国产 App | 顺排     | 「台词拼接」  | 少数有       | 按高度均分  | 模板拼图                 |
| imgtool 拼长图小程序        | 顺排     | 可调字幕间距  | 无           | 无          | 小程序云端               |
| metool 长图切割             | 无       | 无            | 无           | 按高度/切线 | 只做切割                 |
| SmartScrollCapture 等       | 滚动截屏 | 无            | 自动识别重叠 | 无          | 100% 本地                |

结论：这一档就两种核心玩法（无缝顺排、只留底部一条的台词堆叠），差别全在裁切参数上，
所以做成**同一套管线的两个预设**而不是两套代码。真正拉开差距的是重叠自动识别，
它也是唯一一个「算法」而不是「参数」的功能，因此单独拆了匹配器。
横版长图、打码涂抹、设备壳、PDF/GIF 不做（打码要整套编辑层，成本量级不同）。
线上工具普遍有的另外三样 —— 窄图模糊补白、卡片阴影、序号角标 —— 都在这一轮补上了。

## 3. 核心洞察：拼接与拆分共用 `GridTemplate`

拼接是「N 张图 → 一个网格」，拆分是「一张图 → 一个网格的 N 个格子」。数据层是同一个东西：

```ts
type GridTemplate = {
  id: string
  cols: readonly number[] // 归一化权重，和为 1。[0.5,0.5] 两等分；[0.25,0.5,0.25] 即 1:2:1
  rows: readonly number[]
  cells: readonly GridCell[]
}

type GridCell = { col: number; row: number; colSpan?: number; rowSpan?: number }
```

一个类型同时承载三类需求：预设拼接模板（网格 + 不规则跨格）、预设拆分模板（3×3 / 3×9 / 1×3）、
自定义拆分。**拖拽切割线的本质就是改 `cols`/`rows` 里的归一化权重**，不需要为切割线另设数据结构
—— 这让 P2 几乎是免费的。

### 3.1 坐标系：布局归一化，样式绝对像素

- **布局用 0..1 权重**：切换画布比例/尺寸时布局自动适配，图片不跳位。与
  `image-to-beads/selection.ts:1` 的比例选区模型一致。
- **样式用画布真实 px**：`padding: 24` 就是导出图上的 24px，切尺寸时数值不变（视觉占比会变）。
  这是 Canva/PS 的行为，可预测。

## 4. 数据模型

```ts
type Scene = {
  canvas: { width: number; height: number } // 由 ratio + 尺寸档/自定义推出的精确像素
  style: SceneStyle
  grid: { template: GridTemplate; layers: readonly GridLayer[] }
}

type SceneStyle = {
  padding: number // 画布四周留白 px
  gap: number // 单元格间距 px
  cellRadius: number // 单元格圆角 px
  canvasRadius: number // 画布圆角 px（>0 时四角透明，仅 PNG/WebP 有意义）
  background: { type: 'color'; value: string } | { type: 'transparent' }
}

type GridLayer = {
  imageId: string | null // null = 空格子，导出时露背景
  fit: 'cover' | 'contain'
  focus: { x: number; y: number; zoom: number } // cover 裁切偏移，x/y ∈ [-1,1]，zoom ∈ [1,4]
}
```

单向数据流：**用户操作 → 改 store 里的 scene → rAF 重绘 canvas**。渲染唯一入口
`renderSceneToContext(ctx, scene, resolveAsset)`（仿 `image-to-beads/grid-render.ts:20`），
预览画到屏幕 canvas，导出画到同尺寸 OffscreenCanvas。

`resolveCells(template, box, spacing, snap)` 是纯函数，把归一化模板 + px 样式求解成矩形数组，
是单测的主战场。`snap=true` 时轨道边界取整，保证拆分切片**无缝且不重叠**（最后一块吸收取整误差）。

### 4.1 cover 填充的焦点模型

```
scale = max(cell.w/img.w, cell.h/img.h) × zoom      // zoom ≥ 1，保证始终铺满
sw = cell.w / scale ; sh = cell.h / scale            // 实际可见的源图像素
sx = (focus.x + 1) / 2 × (img.w - sw)                // focus ∈ [-1,1]，0 = 居中
```

拖拽单元格时 `focus.x -= dx / cellDisplayWidth × 2`，即拖过半个单元格走完整个裁切行程。

### 4.2 长图的数据模型：纵向流，不是网格

```ts
type LongCrop = {
  keepBottomPercent: number // 创作意图：这张保留底部多少比例，带子恒锚在源图底边
  trimTopPx: number // 去重叠结果：再从顶部裁掉多少源图像素
}

type LongStyle = {
  widthMode: 'narrowest' | 'widest' | 'first' | 'custom'
  targetWidth: number // 仅 custom
  align: 'left' | 'center' | 'right' // 窄于成品宽度的图怎么落位
  padding: number
  gap: number
  stackOverlap: number // 相邻两条带上叠多少 px，做压盖卡片感；0 = 不叠
  canvasRadius: number
  bandRadius: number // 每条带自己的圆角
  narrowFill: 'background' | 'blur' // 窄图两侧是留背景色还是拿自身模糊补白
  shadow: { blur: number; offsetY: number; opacity: number } // blur 0 = 不开
  caption: {
    enabled: boolean
    text: string // 支持 {n} / {total} / {name} 三个占位符
    size: number
    color: string
    place: 'tl' | 'tr' | 'bl' | 'br'
    inset: number
  }
  background: Background
}

type LongBand = {
  imageId: string
  rect: Rect // 成品像素坐标
  sourceTop: number
  sourceHeight: number
  sourceImageHeight: number // 裁切区间的换算基准，降采样预览靠它对回原图
  scale: number // 成品 px / 源图 px
}

type LongLayout = {
  width: number
  height: number
  bands: LongBand[]
  content: { left: number; width: number } // 画布扣掉左右边距那一条，补白照它铺
  segments: Rect[]
  unsplittable: string[]
  maxSegmentHeight: number
}
```

- **裁切用比例不用 px**：产品语言本身就是「保留底部 N%」；`assets.ts` 的 full/preview 是等比
  两级位图，比例模型让预览与导出天然全等；去重叠给的 px 由调用方折算成比例写入。
- **两条顶部通道并存**：最终上沿 = `max(创作上沿, 去重叠上沿)`，识别结果只会把上沿往下推，
  绝不会抬上去，所以重新识别不冲掉用户调好的裁切。
- **首张恒为完整显示**：两种玩法的共同前提，由 `resolveLongLayout` 而不是 UI 保证。
- **一律不放大**：`scale = min(1, 可用宽 / 源宽)`，窄图按原样大小落位并露背景，`align` 决定它靠
  哪边。放大选项排 P3。
- **`sourceImageHeight` 是换算基准**：裁切区间按原图像素存，画降采样预览图时按
  `asset.height / sourceImageHeight` 折算，两级位图共用同一份几何。
- **分段是段的矩形而不是带的分组**：`segments: Rect[]` 纵向无缝首尾相接且
  `Σ height === 整图 height`，切点一定是某条带的上沿，所以既不会切断一张图，也不会重绘两次。
- **`content` 是补白的参照系**：`{left, width}` 就是画布扣掉左右边距那一条。模糊补白铺的是它，
  不是图片自身那一截 —— 否则两侧该被盖住的空白还是空白。`longFillBox()` 只在带子比内容区窄时返回值。
- **相邻上叠进几何而不是进样式**：`flow += gap - stackOverlap`，并且只推到上一条上沿的下一行为止。
  带子 y 一旦反向，分段和导出都会算错；把上一条完全盖住又等于白画一张。
- **外观字段默认全关**：`shadow.blur = 0`、`caption.enabled = false`、`narrowFill = 'background'`、
  两个圆角为 0 —— 不碰参数时成品必须与没有这些字段时逐位一致，这一点由默认值保证而不是靠约定。

## 6. 组件与交互

页面骨架：顶部模式 Tabs（拼接 / 超长图堆叠 / 拆分）→ 左侧舞台 + 素材条，右侧参数卡片，沿用
`ImageToBeads.tsx:302` 的 `grid lg:grid-cols-[minmax(0,1fr)_20rem]`。整页滚动仍只有 `<main>`
一个滚动容器（AGENTS.md §6 app-shell 约定）；长图档在舞台内部另开一块定高缩放视口，
理由见 §10「预览改成固定高度的缩放视口」。

**素材分配**（拼接模式）：新增图片或换模板后，空格子按顺序自动补上未使用的素材
（`images[i] → cells[i]`，已落位的格子不动）。手动调整四条路径：

- **单元格内拖拽** = 平移该格图片的显示区域（focus），双击复位；
- **拖出单元格** = 同一次手势改判为搬移，落到别的格子即交换两格的图（目标为空就是移动），
  跨出瞬间回滚刚才那段平移，避免搬图时顺带把裁切框挪了；同时源格盖一层中性纱表示空出来，
  并渲染一个跟手倾斜的浮层卡片（`position: fixed` + 原图缩到格子的 0.7 倍）作为拖拽影像，
  落点格用蓝色虚线框 + 淡底高亮；松手在格子外即取消，不落位也不留残影；
- **素材条拖到单元格** = 把该素材落进目标格，可重复拖同一张（原生 HTML5 DnD，
  自定义 MIME `text/x-image-stack`）；
- **点选** = 点缩略图拿起「画笔」，再点单元格落位（触屏与键盘路径）。

素材条不用 `@dnd-kit`：它的 PointerSensor 会和「拖去画布」抢同一次指针序列，
而重排本身用原生 drop 到相邻缩略图就够了。

**拆分模式**：素材条点击即选定切分源图；预览用 `<img>` 叠一层 CSS Grid 切割线（不走 canvas，
省一套渲染），编号与导出文件名同为行主序；比例感知裁切提供 居中 / 顶部 / 底部 三个锚点，
且只在原图比目标比例更高时才可用（横图裁切固定居中，锚点无意义时禁用而不是隐藏）。

**长图模式**：三档都是成品在左、工具栏在右，长图档只是把素材条也从舞台下方挪进右栏顶部
（成品那一块已经占满视口高度，下面再压一条素材两边都看不全）。成品是一块固定高度
（`h-[min(72vh,880px)]`）的缩放视口：一列绝对定位的裁切带在里面按 `resolveLongLayout` 的矩形摆位，
带子里那张 `<img>` 用百分比 `height` / `top` 位移到源图的保留区间；缩放是滑杆 + ctrl/⌘ 滚轮，
右侧一栏整图缩览叠一个视口框，点或拖它就跳过去 —— 位置全用比例算，缩放与窗口变化都不重量。
一排玩法 chips（无缝长图 / 台词字幕 / 滚动截图）只是把保留比例与间距设成一组默认值，不是三套代码。
外观三项（窄图模糊补白、单张圆角 + 卡片阴影 + 相邻上叠、序号角标）默认全关，
预览与导出读同一份 `LongStyle`：canvas 侧用 `ctx.filter` / `shadow*` / `fillText`，
DOM 侧用 `filter` / `box-shadow` / 一个 `<span>`，角标两边共用同一个 `CAPTION_FONT` 与同一组锚点。
点带子或点右栏某张即选中它，展开这一张的滑杆，可以「应用到全部」或「恢复继承」；
第一张不给调，因为它恒为完整显示。`自动去重叠` 逐缝取样比对，只有可信的结果自动落值，
`weak / flat / ambiguous` 三种都如实说出来而不是悄悄裁一刀；每条缝也能单独「识别这一处」
（用户点名时弱匹配也照落）与「清除裁切」。

**导出**：拼接 → 单张 blob → 下载 / 剪贴板 / 全屏预览（复用 `components/image-lightbox.tsx`）。
拆分 → 每格一张 blob → jszip 打包，命名 `{原名}_{行}-{列}.{ext}`，同时给逐张下载。

## 7. 错误处理

| 场景                              | 处理                                                                                            |
| --------------------------------- | ----------------------------------------------------------------------------------------------- |
| 解码失败（损坏文件 / 不支持格式） | 该素材标记 `error` 并在缩略图上显示原因，不阻塞其他图                                           |
| 图层数 < 单元格数                 | 空格子导出时露背景色，预览时画占位提示，不报错                                                  |
| 图层数 > 单元格数                 | 多余素材留在素材条未使用，不报错                                                                |
| 画布尺寸非法（0 / 负 / 非有限）   | service 内 `throw Error`（英文技术信息），UI 层捕获降级                                         |
| 画布超大                          | `MAX_CANVAS_SIDE = 8192`、`MAX_CANVAS_AREA = 33_554_432` 提前拦截，避免 canvas 静默失败或内存爆 |
| 样式数值越界                      | `clampStyle` 归一化（负数归零、上限截断），persist 读取时也过一遍                               |
| 剪贴板 API 不可用                 | 按钮禁用 + Tooltip 说明（Firefox/Safari 部分场景）                                              |
| 位图与 objectURL 泄漏             | `assets.ts` 统一 `close()` / `revokeObjectURL()`，卸载与移除素材时回收                          |

  间距只落在带之间、字幕带锚在源图底边、首张恒完整、两条顶部通道取更靠下的那个、
  宽度悬殊时不放大并按 align 落位、边距吃不穿画布宽、0 张与 1 张
- `segmentHeightOf` / segments：切点必落在某条带的上沿、`Σ segment.height === 整图 height`、
  恰好等于上限不切、单张超上限进 `unsplittable`

  `longFillBox` 只在带子窄于内容区时给补白矩形、恰好等宽时返回 `null`；
  `captionText` 的 `{n}` / `{total}` / `{name}`（去扩展名）替换与模板原样透传；
  `captionAnchor` 四角不出带子；`normalizeLongZoom` 把任意输入收进 `[1,4]`
- `normalizeLongStyle` / `normalizeLongCrop`：幂等往返，手工塞 `1e9` / `'12'` / `NaN` /
  非法枚举全部归合法区间
- `matchOverlap`（合成行指纹）：完全一致 → 精确重叠；无公共行 → `none`；无细节行 → `flat`
  且**不返回任何裁切量**；周期图案 → `ambiguous`；代价介于两档阈值之间 → `weak` 但仍给数值；
  多行留白 + 少数文字行仍要认出；`rowStride` 把签名行换算回源图 px；候选上限与下限都封顶

| 两条顶部通道                              | `keepBottomPercent`（创作意图，带子恒锚在源图底边）与 `trimTopPx`（去重叠结果）各自独立，最终上沿取更靠下的那个。这样重新识别不会冲掉用户调好的裁切，反之也不会                                                                                                                                                                                                                                         |
| 逐张微调走数值不走拖拽                    | 上万像素压进半屏后 1 CSS px 相当于四十多个源 px，拖接缝线等于让用户在像素上雕花；侧栏滑杆既精确又自带键盘与触屏可达性。原计划里的「可拖接缝」因此砍掉                                                                                                                                                                                                                                                   |
| 重叠判据从占比改成行数                    | 起初要求「有效行占比 ≥ 60%」，实测立刻把文档截图误判成平场——大段留白 + 少数文字行恰恰是最可靠的重叠。改成只在有证据的行上求平均代价，并要求证据行数 ≥ `min(3, 候选比到的行数)`；上限必须跟着候选收缩，否则 1~2 行的细缝永远凑不齐证据，等于把所有短重叠都判死                                                                                                                                           |
| 证据用行内极差不用相邻列差                | 横向缩到 144px 之后文字被抹成一片灰，相邻列均值差实测降到 0.0002（阈值 0.004），全部行被判平。换成每行亮度极差后同一张图约有四成行带证据，识别在 40 / 200 / 300px 的真实重叠上都精确命中                                                                                                                                                                                                                |
| 让帧要有超时兜底                          | `requestAnimationFrame` 在后台标签页根本不触发，只等它的串行任务（分段导出、逐缝识别）会在用户切走时永远挂着。`yield-frame.ts` 用 rAF 与 24ms 定时器竞速，前台按帧让、后台按拍让                                                                                                                                                                                                                        |
| 逐张覆盖不进 persist                      | `newAssetId()` 每次上传都发新 UUID，按 imageId 存的覆盖刷新后全是孤儿——与拼接的 `layers` 同一个理由，所以 `partialize` 只带 `longStyle / longCropDefaults / longPresetId`，无需提升 version                                                                                                                                                                                                             |
| 插值参数不要叫 count                      | i18next 见到 `count` 会去找 `key_one` / `key_other` 复数形式，基础键里的 `{{total}}` 就没人填了，页面上直接露出花括号。仓内一律用 `total`（见 `filmstrip.count`）                                                                                                                                                                                                                                       |
| 长图导出直接用 full 位图                  | 计划里写了逐张 `decode→draw→close` 的流式导出并给 `ReadyAsset` 加 `file` 字段，实际没必要：`decodeAsset` 本来就把原图留在内存里，拼接档同样是直接取 `full`。加一份并行生命周期只会更容易漏 `close()`                                                                                                                                                                                                    |
| 背景一行抽成组件                          | `StylePanel` 与长图右栏都要「透明 + 色板 + 取色器」，按 AGENTS.md §7 抽出 `BackgroundField` 共用，而不是复制一份                                                                                                                                                                                                                                                                                        |
| 长图档成品在左、工具栏在右                | 原计划让长图档把配置栏放左侧（`lg:grid-cols-[24rem_minmax(0,1fr)]`），实测与另两档反着来要重新学一次列的位置。现在三档统一 `lg:grid-cols-[minmax(0,1fr)_24rem]`，长图档只是额外把素材条从页面底部搬进右栏顶部（`Filmstrip` + `LongConfigPanel` 同列），左栏只剩成品，工具全在右手边                                                                                                                     |
| 预览改成固定高度的缩放视口                | 长图按容器宽摊开就是把一万多像素推进文档流，用户要靠滚轮翻屏才能看完，也谈不上「查看构图」。改成 `h-[min(72vh,880px)] overflow-auto` 的定高视口 + 1×~4× 缩放（⌘/Ctrl + 滚轮，锚在视口中心）+ 右侧按整图比例画定位框的缩览条，点/拖/键盘都能跳看。这一条**反转**了先前「不自建滚动容器、走文档流」的判断：app-shell 约束针对的是整页唯一滚动区，工具内部一块定高视口不与之冲突，另两档的滚动行为一行没动 |
| 长图外观三项默认全关                      | 窄图模糊补白、卡片阴影 + 相邻上叠、序号角标都做成默认关闭的可选项，默认成品仍是一张干净长图。补白靠 `ctx.filter = 'blur()'` + 四周各放大 6% 吃边缘（CSS 侧同名 `filter` + `scale`，同一 `longFillBox` 给矩形），阴影因为 clip 会把投影裁掉只能画进离屏 scratch canvas 再整体贴（CSS 侧直接 `box-shadow`），角标两侧共用 `CAPTION_FONT`、`captionAnchor`、`captionText`，所以字重字距与换行不会漂        |
