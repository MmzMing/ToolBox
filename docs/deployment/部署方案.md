# 部署方案

> 纯前端静态站：`pnpm build` 产物（`dist/`）+ SPA fallback。三套目标环境全覆盖。
> sitemap.xml / robots.txt 的绝对域名取 `src/config/site.ts` 的 `siteUrl`（当前
> `https://tool.mmzhiku.xyz`）；环境变量 `SITE_URL` 只用于临时覆盖（预览环境、换域名灰度）。

## 0. 构建产物

```bash
pnpm install
pnpm build   # prebuild 生成 public/{sitemap.xml,robots.txt,llms.txt,llms-full.txt}
             # → vite build 产出 dist/ → 末尾 scripts/prerender-shells.mjs 写静态壳
```

`public/sitemap.xml` 与 `public/robots.txt` 不入库（gitignore），完全依赖 prebuild 生成；
部署后若 `/robots.txt` 返回的是 `text/html`，说明生成没跑或跑在了 `vite build` 之后。

**预渲染静态壳**：`prerender-shells.mjs` 为每个工具与 `/about` 产出 `dist/<路由>/index.html`
（各自的 title/description/canonical/OG/JSON-LD + 可爬正文），首页 `dist/index.html` 补正文与内链。
托管必须**先查文件再 rewrite** 才会命中：nginx 的 `try_files $uri $uri/ /index.html`、Vercel 与
Netlify 的静态优先都满足；若宿主只认 SPA fallback，请求会退回首页壳（各页 TDK 又变成同一份），
此时用 `curl -s https://<域名>/hash-text | grep "<title>"` 验收，看到的必须是工具自己的标题。

**GEO 入口**：`/llms.txt` 与 `/llms-full.txt` 是给 AI 引擎的站点索引（同样由 prebuild 生成、
不入库），robots.txt 里有一行指路。二者都靠扫描工具注册表生成，新增工具自动进列表。

注意：Vite 8 使用 Hash Router？否——使用 history 路由，**所有平台必须配置 SPA fallback**
（未匹配路径回退 `index.html`），否则深链接/刷新 404。

**静态资源 MIME**：`dist/codecs/**/index.browser.js` 与 `dist/codecs/**/wasm/*.wasm` 由 Worker 在运行时
动态 `import()` / `fetch()`，托管平台必须按扩展名返回 JS MIME（`text/javascript` 或
`application/javascript`）。腾讯云 EdgeOne Pages、Nginx 默认 `mime.types` 等平台**不识别 `.mjs`**
（回落到 `application/octet-stream`），浏览器按严格 MIME 校验拒绝加载，表现为图片压缩转换工具
上传后全部失败——因此编解码器入口一律产出 `.js` 后缀（见 `scripts/prepare-codecs.mjs`）。

## 1. Vercel

方式 A（推荐，零配置）：导入仓库，框架预设自动识别 Vite。
方式 B（配置文件锁定行为）：仓库根目录 `vercel.json`：

```json
{
  "buildCommand": "pnpm build",
  "outputDirectory": "dist",
  "rewrites": [{ "source": "/((?!assets/).*)", "destination": "/index.html" }]
}
```

域名改在 `src/config/site.ts` 的 `siteUrl`（提交进仓库）；只有预览环境需要不同域名时，
才在 Project → Settings → Environment Variables 里配 `SITE_URL` 覆盖。

## 2. Netlify

仓库根目录 `netlify.toml`：

```toml
[build]
  command = "pnpm build"
  publish = "dist"

[build.environment]
  NODE_VERSION = "22"

[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```

`_redirects` 已由 toml 覆盖；预览环境要换域名时在 Site settings → Environment variables 配 `SITE_URL`。

## 3. Cloudflare Pages

| 项        | 值                                          |
| --------- | ------------------------------------------- |
| 构建命令  | `pnpm build`                                |
| 输出目录  | `dist`                                      |
| Node 版本 | 22（环境变量 `NODE_VERSION=22`）            |
| 环境变量  | 可选 `SITE_URL`，缺省用 config 的 `siteUrl` |

SPA fallback：Pages 对静态资源缺失默认回退 404.html；本项目未产出 404.html 文件，
需在 Pages 项目 → Settings → Functions & Routes 开启 **Single-page application** 开关
（或构建后 `rm dist/404.html`，同 it-tools 做法）。

## 4. Docker + Nginx（自有服务器）

多阶段构建 + 非 root + 健康检查（参考 tools-pic 加固方案）。仓库根目录 `Dockerfile`：

```dockerfile
# ---------- 1. 依赖 ----------
FROM node:22-alpine AS deps
WORKDIR /app
RUN corepack enable
COPY package.json pnpm-lock.yaml .npmrc ./
RUN pnpm install --frozen-lockfile

# ---------- 2. 构建 ----------
FROM node:22-alpine AS builder
WORKDIR /app
RUN corepack enable
COPY --from=deps /app/node_modules ./node_modules
COPY . .
# 域名默认取仓库里的 siteUrl；需要覆盖时再打开下一行
# ENV SITE_URL=https://preview.example.com
RUN pnpm build

# ---------- 3. 运行 ----------
FROM nginx:1.27-alpine AS runner
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 8080
USER nginx
HEALTHCHECK --interval=30s --timeout=3s CMD wget -qO- http://127.0.0.1:8080/ >/dev/null || exit 1
CMD ["nginx", "-g", "daemon off;"]
```

`nginx.conf`（SPA fallback + 静态资源缓存 + 安全头）：

```nginx
server {
  listen 8080;
  server_name _;
  root /usr/share/nginx/html;
  index index.html;

  gzip on;
  gzip_types text/css application/javascript application/json image/svg+xml;

  location /assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
    try_files $uri =404;
  }

  location / {
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    try_files $uri $uri/ /index.html;
  }
}
```

运行（最小权限示例）：

```bash
docker build -t toolbox .
docker run -d --name toolbox -p 8080:8080 \
  --read-only --cap-drop ALL \
  --tmpfs /var/cache/nginx:rw --tmpfs /var/run:rw --tmpfs /tmp:rw \
  toolbox
```

反代（宿主 Nginx → 容器）按常规 `proxy_pass http://127.0.0.1:8080;` 配置即可。

## 5. 腾讯云 EdgeOne Pages（当前生产环境）

构建命令 `pnpm build`、输出目录 `dist`、Node 22，在 EdgeOne Pages 控制台配置；
域名取仓库里 `src/config/site.ts` 的 `siteUrl`，无需再配 `SITE_URL`。

平台实测响应头：`.js` → `application/javascript`、`.wasm` → `application/wasm`、
**`.mjs` → `application/octet-stream`（MIME 表缺失，会被浏览器拒绝当模块加载）**。
因此本项目不产出任何 `.mjs` 静态资源；发布后复核一次：

```bash
curl -sI https://<域名>/codecs/oxipng/index.browser.js | grep -i content-type
```
